# LongMindMemEval — MindMate 기억 시스템 재정비 실험

**같은 대화를 기억시키면서 저장 비용을 줄일 수 있을까?**

MindMate 2차 개발 과정에서 기억 저장 모델과 저장 주기를 비교한 개발 실험 자료다.
블로그 설명을 뒷받침할 수 있도록 **실험에 사용한 합성 원문, 사건 정답표, 질문, 실제 답변, 평가 보정, 토큰·비용 기록**을 함께 보관한다.

> 한국어 합성 시나리오 1개 · 10세션 · 조건별 1회 실행.
> 범용 벤치마크나 모델 성능 순위를 주장하는 자료가 아니다. LongMindMemEval은 이 프로젝트의 자체 실험명이며, LongMemEval의 공식 데이터나 확장판이 아니다.

## 핵심 결과

최종 24문항에 대한 기록된 보정을 반영했다. 자동 점수도 함께 공개하며 정답표 자체는 바꾸지 않았다.

| 기억 저장 모델 | 저장 주기 | 저장 실행 횟수 | 자동 정답 / 24 | 보정 반영 / 24 | 10세션 운영 비용 추정 |
|---|---|---:|---:|---:|---:|
| GPT-5.5 | P1 매 세션 | 10 | 20 | **21** | **$1.7739** |
| GPT-5.5 | P3 3세션마다 | 4 | 16 | **16** | **$1.5034** |
| GPT-5.5 | P5 5세션마다 | 2 | 18 | **18** | **$1.1971** |
| GPT-5.4 mini | P1 매 세션 | 10 | 19 | **20** | **$0.5056** |
| GPT-5.4 mini | P3 3세션마다 | 4 | 13 | **14** | **$0.4454** |
| GPT-5.4 mini | P5 5세션마다 | 2 | 17 | **18** | **$0.3166** |

**비용의 의미:** 정상 기억 저장 API 실측 비용(추출·기존 기억 비교·임베딩) + 10회 세션 시작 입력 추정 비용.
시작 입력은 평가용 고정 지시문·공유 기억팩·미정리 원문을 토큰화하여 당시 Realtime 단가로 환산했다. **실제 Realtime 청구액이나 전체 운영 캐릭터·사용자 프로필 프롬프트 비용은 아니다.** 직접 대화·음성·평가 호출·실패 호출은 위 운영 비용에서 제외했다. 제외된 실제 비용은 상세 표에 별도 기록했다.

mini P1은 5.5 P1보다 이 실험에서 최종 정답이 1개 적고 운영 비용 추정은 약 71.5% 낮았다. P5에서는 두 모델 모두 18개를 맞혔고 mini 비용이 약 73.6% 낮았다. 모델별 프롬프트와 출력 한도가 다르므로 **모델 단독 성능 차이로 해석하지 않는다.**

## 데이터와 평가의 범위

- **원문:** 2026-09-03~10-18을 가상 시간축으로 한 합성 대화 10개, user/assistant 합계 206턴.
- **분량:** 세션별 `role: text`를 줄바꿈으로 연결한 뒤 `o200k_base`로 계산해 합산하면 9,560토큰. JSON 메타데이터와 API 프롬프트는 제외한 원문 분량이다.
- **사건:** 발표일 정정(10/22 → 10/29), 복약 중 → 복약 종료, 라멘 경험·비교 취향, 프로젝트 진행, 미정 정보, 저장할 필요 없는 순간적 감탄 등을 배치했다.
- **질문:** 사건 정답표 30개, 질문 정의 95개 = 공통 체크포인트 66 + 발언 직후 5 + 최종 24. 저장 직전 비교 질문과 답변 재사용이 있어 질문 정의 수와 실제 API 호출 수는 다르다.
- **답변 모델:** 모든 조건에서 GPT-4o 고정. 저장 모델의 차이가 제공된 기억에 어떻게 반영되는지 측정했다. Realtime 음성 대화 전체를 평가한 실험은 아니다.
- **채점:** GPT-4o 자동 0/1 채점 + 기록이 남은 Codex 검토·사용자 승인 보정. 검토 모델명을 확실하게 증빙할 기록은 없어 특정 모델로 표기하지 않았다.
- **검색:** 답변할 때 function calling·DB 검색·원문 검색 모두 껐다. 저장 과정에서 기존 기억 후보를 찾는 임베딩·검색은 켜져 있다.
- **보정:** [adjudications.json](results/adjudications.json)에 변경한 답변 ID, 변경 전후 점수, 이유를 보존했다. mini의 최종 문항 보정을 중간 체크포인트 전체에 소급 적용하지 않았다.

## 저장 주기는 무엇이 다른가?

| 방식 | 기억 정리 시점 | 정리 전 다음 세션에 제공하는 내용 |
|---|---|---|
| P1 | 매 세션 종료 | 갱신된 기억팩 |
| P3 | 3·6·9회 종료 + 최종 잔여 10회 | 이전 기억팩 + 아직 정리하지 않은 원문 |
| P5 | 5·10회 종료 | 이전 기억팩 + 아직 정리하지 않은 원문 |

정리를 마치면 해당 원문을 다음 프롬프트에 계속 붙이지 않는다. DB의 원문 자체를 삭제한다는 뜻은 아니다.

## 결과를 읽을 때의 한계

1. 단일 시나리오·조건당 1회다. 통계적 우열이나 일반 사용자 전체의 정확도를 주장할 수 없다.
2. 5.5는 기존 프롬프트, mini는 보완한 v4 추출·갱신 프롬프트를 썼다. 비교 대상은 **모델과 프롬프트 설정의 조합**이다.
3. 5.5 출력 한도는 10,000. mini P1 앞 3회도 10,000이었지만 S04에서 추론으로 한도를 소진했다. S04 재개 이후와 P3/P5는 100,000이었다. 실패 비용 $0.04682235는 따로 보존했다.
4. 과거 사건 만료·기억팩 선별·날짜 필드·답변 모델 때문에도 오답이 생긴다. 모든 오답을 저장 모델의 요약 실패로 해석하지 않는다.
5. 정답이 ‘원문에 없음’인 문항은 모른다고 답하면 맞을 수 있다. 그 정답이 실제 사건을 보존했다는 증거는 아니다.
6. P1/P5의 최종 답변은 S10 체크포인트 답변을 재사용했다. 별도로 24회 재시험한 결과가 아니다. P3만 잔여 원문 정리 후 최종 24문항을 다시 물었다.

상세 해석과 운영 적용 범위: [결과·한계·후속 과제](docs/03-results-and-limitations.md).

## 로컬에서 자료 검증하기

Python 3.10 이상, 기본 검사는 외부 패키지·API 키·DB가 필요 없다.

```bash
python tools/validate.py
```

원문·질문 ID 연결, 세션/턴 수, 미래 근거 유입 여부, 144개 최종 답변, 보정 이력, 자동·최종 합계, 비용·토큰 합계, 파일 해시를 점검한다. 원문 토큰 수를 다시 세려면 `tiktoken`이 설치된 환경에서:

```bash
python tools/validate.py --tokens
```

이 저장소는 **실험 근거 공개 및 집계 재검증용**이다. 유료 모델 호출과 기존 MindMate PostgreSQL 저장 파이프라인을 다시 실행하는 러너는 포함하지 않았다. 단독 clone으로 전체 API 실험을 재현할 수 있다고 주장하지 않는다.
