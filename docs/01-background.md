# 왜 기억 시스템을 재정비했나?

## 1. 출발점: 대화를 다시 켜도 이어지는 로봇

MindMate의 목표는 사용자가 이전에 말한 선호·진행 상황·일정을 기억하고 다음 대화를 이어가는 것이다. 기존 구조는 세션 원문을 보관하고, LLM이 사실을 추출한 뒤 기존 기억과 비교하여 ADD/UPDATE/NOOP/CONFLICT를 결정한다. 다음 대화에 쓰는 기억팩은 이 저장된 사실 중 정책과 문자 예산에 맞는 내용을 골라 만든다.

기억을 단순히 많이 저장하는 것보다 사용자의 현재 상황을 정확하게 반영하는 것이 중요했다. 과거에 약을 먹었던 사실과 지금도 먹는지는 다르다. 발표 예정일이 변경되었으면 현재 날짜를 답하면서 과거 예정일을 구분할 수 있어야 한다.

## 2. 재정비의 계기: 세션 경계마다 발생하는 저장 작업

초기 구현은 대화가 끝날 때마다 추출과 기존 기억 비교를 실행했다. 짧은 대화가 여러 번 끊겨도 매번 정리하므로, 저장 호출 횟수와 반복 입력이 비용 부담이 될 수 있었다. 실제 비용은 원문 길이, 추출 사실 개수, 기존 후보, 출력·추론량, 캐시 적중에 따라 달라진다. 따라서 ‘세션이 많으면 얼마가 든다’는 고정 단가로는 설명하기 어려웠다.

저장 주기를 늘리면 호출 횟수는 줄지만 미정리 원문을 다음 세션에 다시 넣어야 한다. 이 원문도 입력 비용을 만들기 때문에 저장 API 비용만 비교하면 묶음 저장에 유리한 계산이 된다.

## 3. 두 축을 분리해서 보기

- **저장 주기:** 매번 정리할지, 3회 또는 5회 대화를 모아 정리할지.
- **저장 모델:** 기존 GPT-5.5 대신 더 저렴한 GPT-5.4 mini를 사용해도 필요한 기억을 유지할지.

현재 채택할 수 있는 시스템 구성을 찾는 개발 실험이므로 mini에는 해당 모델에서 발견한 누락을 보완한 프롬프트를 적용했다. 이 선택은 실용적인 설정 비교를 가능하게 하지만, 모델 자체만의 능력을 공정하게 분리하는 실험과는 목적이 다르다.

## 4. 왜 실제 대화를 그대로 쓰지 않고 합성 시나리오를 만들었나?

실제 개인 대화만으로는 어떤 정보가 언제 바뀌었는지, 질문 시점에 어떤 답이 맞는지 고정하기 어렵다. 사용자와 함께 사건·날짜·정정 내용을 먼저 정하고, 2학기 캡스톤 준비라는 흐름 안에 user/assistant 대화를 만들었다.

원문은 2026년 9월 3일부터 10월 18일까지의 가상 시간축이다. 1년치 생활 기록을 대표하는 데이터가 아니다. 10세션·206턴·9,560토큰이라는 명시적인 크기의 초기 실험이다.

## 5. 확인하려던 질문

1. 저장을 늦추면 저장 호출 감소가 원문 재입력 비용 증가보다 큰가?
2. 원문을 정리해서 기억팩만 남겼을 때 필요한 정보가 유지되는가?
3. 최신 일정과 과거 일정을 구분하는가?
4. 상태 종료를 반영하면서 과거 경험을 잘못 지우지 않는가?
5. 사용자 확정과 assistant의 제안·예시를 구분하는가?
6. 값이 미정일 때 그럴듯한 내용을 만들지 않는가?
7. 더 저렴한 저장 모델이 실제 사용에 받아들일 만한 품질·비용 절충을 제공하는가?

## 6. 캐싱과 기억은 구분했다

프롬프트 캐시는 같은 입력의 처리 비용을 줄이는 기능이고, 어떤 과거 대화를 다음 세션에 제공할지 결정하는 기억 정책과는 역할이 다르다. 이 실험에서는 사용량 기록의 실제 cached 입력을 반영했으며, 모든 반복 입력이 항상 캐시된다고 가정하지 않았다. 세션 시작 입력은 캐시 할인 없는 별도 추정치다.
