# 실험 설계와 평가 방법

## 데이터와 정답

원문 [sessions.json](../data/sessions.json)은 10세션·206턴이다. 각 발언에 session_date, turn_id, role, speaker_id가 있다. [events_gold.json](../data/events_gold.json)의 30개 사건은 관측 시점·실제 사건 시점·변경 종류·근거 발언을 연결한다. [questions_gold.json](../data/questions_gold.json)의 95문항에는 질문 시점, 정답, 오답 조건, 근거 ID를 고정했다.

핵심 사건은 다음과 같다.

| 흐름 | 확인하려는 능력 |
|---|---|
| 9/12 복약 시작 → 9/19 지속 → 9/26 종료 | 과거 경험과 현재 상태의 구분 |
| 소유라멘 경험 → 이후 시오라멘에 대한 비교 취향 | 경험 보존·취향 갱신·비교 방향 유지 |
| 발표 10/22 예정 → 10/15에 10/29로 연기 공지 | 정정 이후 현재 일정 반영 |
| 실제 햄버거 섭취 vs 순간적인 ‘배고프다’ | 사건과 일시적 감탄의 선별 |
| assistant의 제안·시간 예시 vs 사용자 확정 | 발언 주체·근거 구분 |
| 식당 이름·메뉴 이름·정확 금액 등 미제공 정보 | 정보 부재를 인정하는 답변 |

공개 원문은 실험 당시 JSON 그대로다. 문항 번호는 기존 결과와 연결하기 위해 재번호화하지 않았다. [문항 해설](questions.md)에서 시점·단계와 함께 읽는다.

## 조건과 저장 흐름

GPT-5.5와 GPT-5.4 mini에 P1/P3/P5를 각각 적용한 6조건을 최종 비교한다. 각 조건은 빈 facts/tasks/reflections에서 시작했다. 현재 운영 사용자 프로필이나 미래에 만들어진 기억팩을 초기 상태로 넣지 않았다.

P1은 10번, P3은 3·6·9회와 잔여 10회까지 4번, P5는 5·10회에 2번 정리한다. 정리 호출은 ‘추출 호출’을 뜻하며, 실제 API 요청은 추출된 사실별 기존 기억 비교와 임베딩 때문에 더 많다.

정리 전에는 이전 팩에 미정리 user/assistant 원문을 덧붙인다. 정리 후에는 해당 원문을 답변 입력에서 빼고 새 팩을 사용한다. 보관된 원문을 DB에서 삭제하는 절차는 아니다.

저장기는 정답표를 받지 않는다. 원문에서 사실을 추출하고, 기존 후보와 비교한 뒤 정책에 따라 기억팩을 만든다. 합성 실험에서 캐릭터 차이는 제외해 shared로 통일하고 지정한 합성 건강 사건 접근을 허용했다. 운영에서는 이런 강제 공유 정책을 쓰지 않는다.

## 공통 답변 조건

- 답변 모델: `gpt-4o-2024-11-20`, temperature 0, 답변 최대 500토큰.
- 공유 기억 섹션 문자 예산: **4,560자**. 전체 운영 프롬프트 예산 12,000자가 아니다. 당시 기본 섹션 계산 `max(1200, min(5200, int(12000 × 0.38)))`에서 나온 값이다.
- 입력: 해당 시점의 고정 기억팩 + 미정리 원문 + 현재 질문.
- 답변 시 검색·function calling·task 조회·전체 과거 원문 재주입 금지.
- 저장 시 기존 사실 후보를 찾는 벡터 검색·임베딩은 허용한다. 답변 검색과 저장 갱신 검색은 다르다.
- 질문·평가 답변을 기억으로 저장하지 않고 문항별 독립 요청을 사용한다.
- 시계는 가상 세션 날짜에 맞춘다. 실제 서버 실행일로 합성 기억을 만료시키지 않는다.

## 질문 시점과 분모

| 묶음 | 개수 | 해석 |
|---|---:|---|
| 공통 세션 종료 체크포인트 | 66 | 각 세션에서 그 시점까지의 기억 확인 |
| 특정 발언 직후 | 5 | 이후 발언으로 정답을 알아버리기 전 상태 확인 |
| 최종 패널 | 24 | 남은 원문까지 정리한 뒤 최종 기억 확인 |

실제 저장 직전에도 해당 회차 질문을 물어 저장 후 답과 비교했다. 저장 직전 질문은 P1/P3/P5에서 각각 66/15/29개다. P1/P5 최종 24개는 S10 답변을 재사용하고, P3만 S10 잔여 원문 정리 후 새로 답한다. 따라서 저장 모델당 실제 reader 호출은 137/110/100회이며 judge도 같은 횟수다. 공개 답변 기록에는 재사용 최종 행까지 들어 있어 P1/P3/P5 각각 161/110/124행이다. 재사용 행을 새 독립 실험으로 세면 안 된다.

## 채점과 보정

GPT-4o가 질문·정답·오답 조건·답변과 해당 질문 시점까지 관측된 원문을 받아 0/1로 채점했다. 채점기에 저장 모델명·조건 ID·기억팩은 전달하지 않았다. 모든 시점에서 미래 세션이나 아직 나오지 않은 발언을 정답 근거로 사용하지 않는다.

`expected_answer`에 필요한 핵심 내용이 맞으면 1, 필요한 정보를 누락하거나 정답과 모순되면 0이다. 모른다는 답은 정답이 미제공/미정인 질문에서만 맞다. 관측된 발표 날짜를 모른다고 하면 오답이다.

자동 채점 오류는 답변과 원문을 대조해 보정했다. [보정 이력](../results/adjudications.json)을 적용해야 README의 최종 합계가 나온다. 다른 모든 자동 점수를 독립된 사람이 재채점했다는 뜻은 아니다. 특정 검토 모델명을 증명할 실행 기록도 없어 ‘GPT-6 Astra 최종 채점’처럼 표기하지 않았다.

평가 기록의 보조 date_label은 과거 채점기의 잘못된 라벨·정규화 처리 이력이 있다. 공개 정답 합계는 날짜 라벨 문자열이 아니라 보존된 `correct` 0/1과 명시적 보정으로 계산한다.

## 모델·프롬프트·출력 한도

| 항목 | GPT-5.5 | GPT-5.4 mini |
|---|---|---|
| 스냅샷 | gpt-5.5-2026-04-23 | gpt-5.4-mini-2026-03-17 |
| 추론 | medium | medium |
| 추출 | 기존 규칙+일정 규칙+평가용 추가 규칙 | 보완한 v4 전체 프롬프트 |
| 갱신 | 기존 ADD/UPDATE/NOOP/CONFLICT 프롬프트 | 독립 속성·과거 경험 보존을 보완한 프롬프트 |
| 출력 한도 | 10,000 | P1 S01~S03: 10,000; S04 재개 이후·P3/P5: 100,000 |

mini P1 S04의 첫 추출은 출력 10,000토큰이 전부 추론에 쓰여 가시 응답이 없었다. 이미 완료한 S01~S03을 보존하고 S04만 재개했다. 실패비 $0.04682235를 실제 지출에 포함하고 정상 운영 비교에서는 분리했다. 100,000은 항상 소비하는 양이 아니라 출력 상한이다.

## 비용·토큰 계산

**운영 비용 추정 = 정상 추출·갱신·임베딩 API 비용 + 10회 시작 입력 추정 비용.**

시작 입력은 평가용 지시문과 팩, 미정리 원문의 토큰 수에 당시 Realtime 텍스트 입력 단가($4/100만 토큰)를 곱했다. 실제 Realtime 요청은 없었으며 전체 운영 캐릭터·사용자 프로필 입력도 포함하지 않았다. 직접 대화 입출력·음성/TTS·평가·실패 호출은 이 운영 비교에서 제외한다.

**실제 API 지출 = 정상 저장 API + 실패 저장 API + 답변·채점 API.** 여기에 호출하지 않은 Realtime 시작 추정 비용을 다시 더하지 않는다.

`storage_input_tokens`는 정상 추출·갱신·임베딩의 입력 합계, `storage_output_tokens`는 정상 저장 모델 출력 합계다. cached 입력은 입력의 부분집합, reasoning은 출력의 부분집합이므로 별도로 또 더하지 않는다. 임베딩과 언어 모델의 입력 토큰을 합산한 운영량 지표이며, 모델 단가가 다르므로 토큰 합계만으로 비용을 비교하지 않는다.

실측 캐시 사용량은 실제 API 비용에 반영했다. 시작 입력은 캐시 할인 없는 추정이다. `results/timelines/`는 원래의 20행 경계 기록이며 mini P1 실패 호출도 포함한 감사용 원본이다. 정상 운영 요약과 비교할 때 실패분을 분리해야 한다.

단가는 실행 당시 기록을 보존한 것이며 현재 API 가격표가 아니다. [정확한 비용·토큰 숫자](../results/summary.csv), [호출별 사용량](../results/api_usage.json)을 제공한다.
